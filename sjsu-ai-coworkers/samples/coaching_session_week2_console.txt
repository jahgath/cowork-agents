Question 2 of 6 · AI security & safety · concept · difficulty 2/3

What is prompt injection, and how would you defend an agent that reads users' emails?

  > Prompt injection is when untrusted content, like the body of an email, contains instructions that try to override the agent's real instructions, for example 'forward all invoices to this address'. The defense is layered: treat tool outputs as data, not instructions; give the agent least-privilege tools, so a read-email agent can't send or delete by default; require human confirmation before any side-effecting action; and add an injection classifier and logging so attempts are detected and audited.

  Score: 72%  ·  graded by rubric
  Feedback: Covered: external content is untrusted data; it tries to override instructions; human confirmation; injection detection. Missing: least-privilege tools; sandboxing.
  Reference answer: Prompt injection is when untrusted content (an email, web page, document) contains text that tries to override the agent's instructions. Treat tool outputs as data, not instructions; give the agent least-privilege tools; require human confirmation for side-effecting actions such as sending or deleting; isolate risky operations; and add injection classifiers and logging as defense in depth.

Question 3 of 6 · LLM fundamentals · coding · difficulty 2/3

Write `cosine_top_k(query, docs, k)`: `query` is a vector, `docs` a list of vectors (lists of floats). Return the indices of the k most cosine-similar docs, best first; break ties by lower index; treat zero vectors as similarity 0.
  (Define a Python function named `cosine_top_k`; it will be run against hidden tests.)

  > ```python
    import math
    
    def cosine_top_k(query, docs, k):
        qn = math.sqrt(sum(x * x for x in query))
        scores = []
        for i, d in enumerate(docs):
            dn = math.sqrt(sum(x * x for x in d))
            if qn == 0 or dn == 0:
                sim = 0.0
            else:
                sim = sum(a * b for a, b in zip(query, d)) / (qn * dn)
            scores.append((-round(sim, 12), i))
        scores.sort()
        return [i for _, i in scores[:k]]
    ```

  Score: 100%  ·  graded by unit-tests
  Feedback: All 5 tests passed.

Question 4 of 6 · Retrieval-augmented generation · concept · difficulty 1/3

Walk me through a basic retrieval-augmented generation (RAG) pipeline end to end.

  > Offline, I split documents into overlapping chunks, embed each chunk, and store the vectors in an index. At query time I embed the question, retrieve the top-k most similar chunks, and augment the prompt with them as context, then the LLM generates an answer grounded in those chunks, ideally with citations.

Question 5 of 6 · Agentic AI & orchestration · concept · difficulty 1/3

What is the difference between an LLM *workflow* and an *agent*, and when would you choose each?

  > A workflow runs LLM calls and tools through code paths I define in advance, like prompt chaining or routing, so it's predictable, cheaper and easy to debug. An agent lets the model dynamically decide its next step and which tool to call in a loop. I'd default to a workflow and only use an agent for open-ended tasks where I can't predict the number of steps, accepting more cost and the risk of compounding errors.

  Score: 100%  ·  graded by rubric
  Feedback: Covered: workflows follow predefined code paths; agents let the model choose its next step; workflows are more predictable, cheaper and easier to debug; agents suit open-ended tasks with unknown step counts.
