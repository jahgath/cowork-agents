Question 3 of 6 · Agentic AI & orchestration · coding · difficulty 3/3

Agent planners often run tasks as a DAG. Write `topo_order(deps)` where `deps` maps each task to the list of tasks it depends on. Return an order in which every task appears after its dependencies, choosing the alphabetically smallest available task at each step. Return `[]` if there is a cycle. Tasks that appear only as dependencies are tasks too.
  (Define a Python function named `topo_order`; it will be run against hidden tests.)

  > ```python
    import heapq
    
    def topo_order(deps):
        nodes = set(deps)
        indeg = {n: 0 for n in nodes}
        children = {n: [] for n in nodes}
        for task, ds in deps.items():
            for d in ds:
                indeg[task] += 1
                children[d].append(task)
        ready = [n for n in nodes if indeg[n] == 0]
        heapq.heapify(ready)
        order = []
        while ready:
            n = heapq.heappop(ready)
            order.append(n)
            for c in children[n]:
                indeg[c] -= 1
                if indeg[c] == 0:
                    heapq.heappush(ready, c)
        return order
    ```

Question 4 of 6 · Agentic AI & orchestration · concept · difficulty 2/3

In LangGraph, explain state, nodes, edges and checkpointers. Why does checkpointing matter for a human-in-the-loop agent?

  > State is a shared TypedDict that every node reads and updates. Nodes are just Python functions, and edges connect them, including conditional edges that route based on the state. A checkpointer saves the state after each step so if the graph hits an interrupt it can pause, wait for a human to approve, and then resume from the same point later.

  Score: 100%  ·  graded by rubric
  Feedback: Covered: state as a shared typed object; nodes as functions; edges and conditional routing; checkpointers persist state; pause/resume for human approval.
